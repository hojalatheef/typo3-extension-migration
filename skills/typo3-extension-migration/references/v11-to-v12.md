# TYPO3 v11 → v12: extension migration cards

> Target platform: PHP 8.1–8.3 on TYPO3 12.4 LTS (8.4 only in late 12.4 patch/ELTS levels; check the release notes), composer constraint `typo3/cms-core: ^12.4`, Doctrine DBAL 3.x, Symfony 6.x, PHP extensions `mbstring` and `intl` required.
> Order of attack:
> 1. Make sure every v11 deprecation is gone first (see v10-to-v11.md): ObjectManager, `@inject`, `TYPO3_MODE`, `forward()`, non-Response actions, `BackendTemplateView`, SignalSlot — all removed in v12.0 and fatal.
> 2. Move registrations out of `ext_tables.php`: backend modules → `Configuration/Backend/Modules.php`, icons → `Configuration/Icons.php`, JS → `Configuration/JavaScriptModules.php`, page TSconfig → `Configuration/page.tsconfig`.
> 3. Run Rector `Typo3LevelSetList::UP_TO_TYPO3_12` (TCA type migrations, DBAL, Extbase redirects) and Fractor (FlexForm `TCEforms`, TypoScript); review TCA diffs field by field.
> 4. Replace removed hooks with PSR-14 listeners, then port RequireJS/AMD modules to ES modules.
> 5. Verify: Extension Scanner, deprecation log, "TCA migrations" check in the Upgrade module (it lists every runtime-migrated TCA/FlexForm option still in your code).
