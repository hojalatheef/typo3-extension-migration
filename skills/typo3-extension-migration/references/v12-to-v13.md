# TYPO3 v12 → v13: extension migration cards

> Target platform: PHP 8.2–8.4 (8.2 minimum is hard; upper bound per 13.4 patch release: verify), composer constraint `typo3/cms-core: ^13.4`, MySQL 8.0.17+ / MariaDB 10.4.3+ / PostgreSQL 10+ / SQLite 3.8.3+, Doctrine DBAL 4, Fluid standalone 4.x in 13.4 (verify). `ext_emconf.php` is still read in classic mode: keep it and set `'typo3' => '13.4.0-13.4.99'` in `constraints.depends` alongside `composer.json`.
> Order of attack:
>
> 1. Raise PHP/composer/ext_emconf constraints, run Rector sets `Typo3LevelSetList::UP_TO_TYPO3_13` plus Fractor for TypoScript/TSconfig; commit the result on its own.
> 2. Fix everything that fatals on v13.0: removed v12-deprecated APIs (`_GP`, `addModule`, `AbstractPlugin`, `TemplateService`), DBAL 4 QueryBuilder/Connection, `TSFE->fe_user`, strict Extbase types.
> 3. Frontend state: replace every `$GLOBALS['TSFE']` read with request attributes. It is deprecated in 13.4 and gone in v14, so doing it now pays twice.
> 4. Plugins: move `list_type` plugins to their own `CType` and ship an upgrade wizard. `StandaloneView` goes to `ViewFactoryInterface`, and `renderStatic()` ViewHelpers become `render()`.
> 5. Cleanup that v14 makes mandatory: drop redundant `ext_tables.sql` columns, move `addPageTSConfig` to `Configuration/page.tsconfig`, IconRegistry calls to `Configuration/Icons.php`, and hooks to PSR-14 events.
> 6. Run the extension scanner and the DB analyzer (`bin/typo3 extension:setup`, then the Upgrade > Analyze Database Structure module), then run tests on 13.4 with the deprecation log enabled.

## Database and TCA

### ext_tables.sql: columns now derived from TCA

- **Status:** breaking in v13.0 (datetime columns now BIGINT; auto-creation extended to nearly all TCA types)
- **Detect:** `^ *(tstamp|crdate|deleted|hidden|starttime|endtime|sorting|sys_language_uid|l10n_parent|l10n_diffsource|t3ver_[a-z_]+) +(int|tinyint|smallint|varchar|mediumblob|text)`
- **Replace with:** Delete column definitions that TCA already describes: `ctrl` management fields and, since v13, most `columns` types (input, text, check, select, group, inline, file, number, link, email, flex, ...). Keep an explicit definition only where you need a non-default type or length. For `type=select` columns, `dbFieldLength` sets the varchar length. After you change the file, compare the result in the DB analyzer. `type=datetime` columns without an explicit definition become signed BIGINT.
- **Keep:** The file rarely disappears completely. Keep:
  - tables without TCA (import or cache tables written through `ConnectionPool` only)
  - columns that are not in the table's TCA
  - every index: TCA cannot declare `KEY` or `UNIQUE KEY`, and dropping a lookup index on a large detail table turns each query into a full scan
  - an MM table whose code relies on its own `uid` primary key. The auto-created MM table uses the primary key `(uid_local, uid_foreign)` unless the field sets `multiple`, so a duplicate pair that used to insert fine now fails. Inside an import transaction, that rolls back the whole run.

  Do not add TCA to a table only to empty its block in `ext_tables.sql`. That turns an internal table into a backend record type and still leaves its indexes in the file.
- **Prove it:** Compare the schema before and after the edit. Before, the compare must be clean for the extension's tables. After, expect only `CHANGE` and index statements and no `DROP` or `zzz_deleted_` rename, unless you removed a column on purpose. On 14.3, typical changes are:
  - management fields become `INT UNSIGNED` or `SMALLINT UNSIGNED`
  - `type=input` columns become `VARCHAR(255)`
  - the `parent` index becomes `(pid, deleted, hidden)`

  Use Install Tool > Analyze Database Structure (core), or, with `helhum/typo3-console`, `typo3 database:updateschema safe,destructive --dry-run --raw`. Check that command's exit code: a mangled argument such as `'*'` passed through `ddev exec` prints only the usage and no SQL, which looks exactly like a clean compare.
- **Automation:** manual
- **Changelog:** Breaking-99937-DateTimeTCAFieldsToBigint, Feature-101553-Auto-createDBFieldsFromTCAColumns

### TCA ctrl `cruser_id` leftover

- **Status:** removed in v12.0 (still commonly present in extensions)
- **Detect:** `cruser_id`
- **Replace with:** Remove the `ctrl.cruser_id` entry, the `ext_tables.sql` column, and any code that reads or writes it. The record history (sys_history) is the source for "created by". Grep all of `Classes/`, not only TCA: legacy import code often writes it through a raw `INSERT` or a `ConnectionPool` row array, usually hard-coded to `1`. Remove that write in the same change as the column, or the next insert fails with an unknown column. The DB compare removes the column in two runs: first it renames it to `zzz_deleted_cruser_id`, then it drops it.
- **Automation:** manual (TCA migration strips it at runtime and logs it)
- **Changelog:** Breaking-98024-TCA-option-cruserid-removed

- **Automation:** Rector `RemoveMmHasUidFieldRector`
- **Changelog:** Deprecation-101554-ObsoleteTCAMM_hasUidField

### Plugin sub types (`list_type`) → own CType

- **Status:** deprecated v13.4 (removed in v14.0)
- **Detect:** `list_type|subtype_value_field|subtypes_addlist|subtypes_excludelist|PLUGIN_TYPE_PLUGIN`
- **Replace with:** Register each plugin as a content type: call `ExtensionUtility::configurePlugin()` with the 5th argument `ExtensionUtility::PLUGIN_TYPE_CONTENT_ELEMENT`, and call `registerPlugin()` in `Configuration/TCA/Overrides/tt_content.php`. Give each plugin its own `types[<ctype>]['showitem']` (add `pi_flexform` there), and move FlexForm `ds` entries keyed `'<sig>,list'` to the CType. Ship an upgrade wizard that extends `AbstractListTypeToCTypeUpdate` (v13: `TYPO3\CMS\Install\Updates\`, attribute `TYPO3\CMS\Install\Attribute\UpgradeWizard`) and maps the old list_type values to the new CTypes.
- **Automation:** Rector `MigratePluginContentElementAndPluginSubtypesRector`, `MigratePluginContentElementAndPluginSubtypesTCARector`, `MigratePluginContentElementAndPluginSubtypesSwapArgsRector`, `RemoveTcaSubTypesExcludeListTCARector`; the wizard is manual

## Frontend: TSFE and request attributes

### `$GLOBALS['TSFE']` and TypoScriptFrontendController

- **Status:** deprecated v13.4 (most members internal/read-only since v13.0; removed in v14.0)
- **Detect:** `\$GLOBALS\[.TSFE.]|getTypoScriptFrontendController\(|frontend\.controller`
- **Replace with:** Read state from the PSR-7 request. Page data comes from `frontend.page.information` (`getId()`, `getPageRecord()`, `getRootLine()`, `getContentFromPid()`, `getLocalRootLine()`). TypoScript comes from `frontend.typoscript` (`getConfigArray()`, `getSetupArray()`). Language comes from `language`, and routing from `routing`. For `sys_page`, create your own `PageRepository`. For `cObj`, create a `ContentObjectRenderer`, then call `setRequest()` and `start()`.
- **Automation:** Rector `MigrateTypoScriptFrontendControllerReadOnlyPropertiesRector`, `MigrateTypoScriptFrontendControllerConfigRector`, `MigrateTypoScriptFrontendControllerConfigRootLineRector`, `MigrateTypoScriptFrontendControllerSysPageRector`, `MigrateTypoScriptFrontendControllerMethodCallsRector`, `MigrateTypoScriptFrontendControllerGetContextRector`
- **Changelog:** Breaking-102621-MostTSFEMembersMarkedInternalOrRead-only

```php
// before
$pageId = $GLOBALS['TSFE']->id;
$config = $GLOBALS['TSFE']->config['config'];
// after
$pageId = $request->getAttribute('frontend.page.information')->getId();
$config = $request->getAttribute('frontend.typoscript')->getConfigArray();
```
