# TYPO3 v10 → v11: extension migration cards

> Target platform: PHP 7.4–8.1 on TYPO3 11.5 LTS (PHP 8.2+ only in later ELTS patch levels; check the release notes), composer constraint `typo3/cms-core: ^11.5`, Doctrine DBAL 2.13, Symfony 5.4 components.
> Order of attack:
>
> 1. Fix packaging first: `composer.json` with `extra.typo3/cms.extension-key`, `^11.5` constraints, ext_emconf `depends` → `typo3 => 11.5.0-11.5.99`.
> 2. Fix the hard v11.0 breaks that fatal on first request: vendor-prefixed plugin/module registration, Fluid widgets, Extbase `$this->response` API, `Configuration/Commands.php`, `TEMPLATE` cObject.
> 3. Run Rector with `Typo3LevelSetList::UP_TO_TYPO3_11` and Fractor for Fluid/TypoScript; review each diff, do not bulk-accept.
> 4. Then clear the v11 deprecations (ObjectManager, `@inject`, `TYPO3_MODE`, non-Response actions, `forward()`): they are all removed in v12, so doing them now makes the next jump mechanical.
> 5. Verify with the Extension Scanner (Upgrade module) and the deprecation log enabled.

## Packaging and bootstrap

### composer.json must declare the extension key

- **Status:** deprecated v11.4 (extensions not installed via Composer in Composer mode); a missing `extension-key` triggers a warning from `typo3/cms-composer-installers` (exact severity depends on the installer version — verify)
- **Detect:** `"type"[[:space:]]*:[[:space:]]*"typo3-cms-extension"` (then check that `extra.typo3/cms.extension-key` is present)
- **Replace with:** Add `"extra": {"typo3/cms": {"extension-key": "my_ext"}}` and a `typo3/cms-core: ^11.5` requirement. In Composer mode every extension must be installed through Composer; extensions lying around in `typo3conf/ext/` without a Composer package are deprecated.
- **Automation:** manual
- **Changelog:** Deprecation-94996-InComposerModeAllExtensionsShouldBeInstalledWithComposer

### `TYPO3_MODE` / `TYPO3_REQUESTTYPE` constants

- **Status:** deprecated v11.0, removed v12.0
- **Detect:** `TYPO3_MODE|TYPO3_REQUESTTYPE`
- **Replace with:** File guard `defined('TYPO3') or die();`. Context checks via `ApplicationType::fromRequest($request)->isFrontend()` / `->isBackend()` (`TYPO3\CMS\Core\Http\ApplicationType`).
- **Automation:** Rector `\Ssch\TYPO3Rector\TYPO311\v0\SubstituteConstantsModeAndRequestTypeRector`
- **Changelog:** Deprecation-92947-DeprecateTYPO3_MODEAndTYPO3_REQUESTTYPEConstants

```php
// before
defined('TYPO3_MODE') or die();
if (TYPO3_MODE === 'BE') { ... }
// after
defined('TYPO3') or die();
if (ApplicationType::fromRequest($GLOBALS['TYPO3_REQUEST'])->isBackend()) { ... }
```

### `TYPO3_version` / `TYPO3_branch` constants

- **Status:** deprecated v10.3, removed v12.0
- **Detect:** `TYPO3_version|TYPO3_branch`
- **Replace with:** `GeneralUtility::makeInstance(\TYPO3\CMS\Core\Information\Typo3Version::class)->getMajorVersion()` / `->getBranch()`.
- **Automation:** Rector `\Ssch\TYPO3Rector\TYPO310\v3\UseClassTypo3VersionRector`

### Extbase `EnvironmentService`

- **Status:** deprecated v11.2, removed v12.0
- **Detect:** `EnvironmentService|isEnvironmentInFrontendMode|isEnvironmentInBackendMode`
- **Replace with:** `ApplicationType::fromRequest($request)`.
- **Automation:** Rector `\Ssch\TYPO3Rector\TYPO311\v2\SubstituteEnvironmentServiceWithApplicationTypeRector`
- **Changelog:** Deprecation-92494-ExtbaseEnvironmentService

### Leftover path constants from v9

- **Status:** removed v10.0 (still found in extensions that were "made v10 compatible" by constraint only)
- **Detect:** `PATH_site|PATH_typo3conf|PATH_typo3|PATH_thisScript|TYPO3_OS`
- **Replace with:** `\TYPO3\CMS\Core\Core\Environment::getPublicPath()`, `::getConfigPath()`, `::getVarPath()`, `::isWindows()`.
- **Automation:** Rector (TYPO3_9 set)

### CLI commands in `Configuration/Commands.php`

- **Status:** removed v11.0 (deprecated v10.3)
- **Detect:** file `Configuration/Commands.php` exists (`find . -path '*/Configuration/Commands.php'`)
- **Replace with:** Register the command in `Configuration/Services.yaml` with tag `console.command` (attribute `command: 'myext:foo'`); delete Commands.php.
- **Automation:** manual

```yaml
  Vendor\MyExt\Command\ImportCommand:
    tags:
      - name: console.command
        command: 'myext:import'
        description: 'Import records'
```

## Extbase: registration and controllers

### Vendor prefix and short controller names in `configurePlugin()` / `registerModule()`

- **Status:** breaking in v11.0 (deprecated v10.0)
- **Detect:** `^[[:space:]]*'[A-Z][A-Za-z0-9]*\.[A-Z][A-Za-z0-9.]*'[[:space:]]*,` (vendor-dotted extension name argument) and `=>[[:space:]]*'[a-z]+(,[[:space:]]*[a-z]+)*'` next to non-FQCN controller keys
- **Replace with:** Pass the extension name without vendor (`'MyExt'`) and key controller-actions by FQCN: `[\Vendor\MyExt\Controller\ItemController::class => 'list, show']`.
- **Automation:** Rector (TYPO3_10 set) partially; verify every call
- **Changelog:** Breaking-92609-UseControllerClassesWhenRegisteringPluginsmodules

### Extbase actions should return `ResponseInterface`

- **Status:** deprecated v11.0, required in v12.0
- **Detect:** `public function [a-zA-Z0-9]+Action\([^)]*\)[[:space:]]*(:[[:space:]]*void)?[[:space:]]*$` (actions without a return type)
- **Replace with:** Declare `: ResponseInterface` and `return $this->htmlResponse();` (or `$this->jsonResponse($json)`, or a PSR-7 response from `ResponseFactoryInterface`).
- **Automation:** Rector `\Ssch\TYPO3Rector\TYPO311\v0\ExtbaseControllerActionsMustReturnResponseInterfaceRector`
- **Changelog:** Deprecation-92784-ExtbaseControllerActionsMustReturnResponseInterface

### `ActionController::forward()`

- **Status:** deprecated v11.0, removed v12.0
- **Detect:** `\$this->forward\(`
- **Replace with:** `return (new \TYPO3\CMS\Extbase\Http\ForwardResponse('show'))->withControllerName('Item')->withArguments(['item' => $item]);`
- **Automation:** Rector `\Ssch\TYPO3Rector\TYPO311\v0\ForwardResponseInsteadOfForwardMethodRector`
- **Changelog:** Deprecation-92815-ActionControllerForward

### Extbase `$this->response` (non-PSR-7) API

- **Status:** breaking in v11.0
- **Detect:** `\$this->response->(setHeader|appendContent|setContent|setStatus|getContent|addAdditionalHeaderData)`
- **Replace with:** Build and return a PSR-7 response: `return $this->htmlResponse($html)->withHeader('X-Foo', 'bar')->withStatus(201);`. `Mvc\Web\Response` is gone; Extbase handles PSR-7 responses only.
- **Automation:** manual
- **Changelog:** Breaking-92502-MakeExtbaseHandlePSR7ResponsesOnly

### `StopActionException` and redirects

- **Status:** deprecated v11.3, removed v12.0
- **Detect:** `StopActionException`
- **Replace with:** Stop catching/throwing it. In v11 `redirect()`/`redirectToUri()` still throw internally; in v12 they return a `ResponseInterface`, so write `return $this->redirect('list');` (safe on both).
- **Automation:** Rector `\Ssch\TYPO3Rector\TYPO312\v0\ExtbaseActionsWithRedirectMustReturnResponseInterfaceRector` (run it when you move to v12)
- **Changelog:** Deprecation-94351-ExtextbaseStopActionException

### Extbase `ViewInterface` and `AbstractView`

- **Status:** deprecated v11.5, removed v12.0
- **Detect:** `TYPO3\\CMS\\Extbase\\Mvc\\View\\(ViewInterface|AbstractView|EmptyView)`
- **Replace with:** Type-hint `\TYPO3Fluid\Fluid\View\ViewInterface`; drop `canRender()` usage; custom views implement the Fluid interface.
- **Automation:** Rector `\Ssch\TYPO3Rector\TYPO311\v5\MigrateExtbaseViewInterfaceRector`
- **Changelog:** Deprecation-95222-ExtbaseViewInterface

### `ControllerContext`

- **Status:** deprecated v11.5, removed v12.0
- **Detect:** `getControllerContext\(|ControllerContext`
- **Replace with:** Use `$this->request`, `$this->uriBuilder`, and `$this->addFlashMessage()` directly; in ViewHelpers read the request from `$renderingContext->getRequest()` (v11.5+; verify for your ViewHelper base class).
- **Automation:** Rector `\Ssch\TYPO3Rector\TYPO312\v0\MigrateGetControllerContextGetUriBuilderRector` (covers the UriBuilder case only)
- **Changelog:** Deprecation-95139-ExtbaseControllerContext

### Extbase `Request::getBaseUri()` / `getRequestUri()`

- **Status:** deprecated v11.3, removed v12.0
- **Detect:** `->(getBaseUri|getRequestUri)\(`
- **Replace with:** Extbase `Request` implements `ServerRequestInterface` since v11.3: `$this->request->getAttribute('normalizedParams')->getSiteUrl()` / `->getRequestUri()`.
- **Automation:** Rector `\Ssch\TYPO3Rector\TYPO311\v3\SubstituteExtbaseRequestGetBaseUriRector`
- **Changelog:** Deprecation-94223-ExtbaseRequest-getBaseUri

### Generic Extbase `FrontendUser` / `FrontendUserGroup` classes

- **Status:** deprecated v11.4, removed v12.0
- **Detect:** `TYPO3\\CMS\\Extbase\\Domain\\(Model|Repository)\\(FrontendUser|FrontendUserGroup|BackendUser|BackendUserGroup)`
- **Replace with:** Ship your own model + repository mapped to `fe_users` / `fe_groups` via `Configuration/Extbase/Persistence/Classes.php`.
- **Automation:** manual
- **Changelog:** Deprecation-94654-GenericExtbaseDomainClasses

### `Typo3QuerySettings` language mode

- **Status:** deprecated v11.0 (language handling replaced by `LanguageAspect` in v12.0)
- **Detect:** `->(setLanguageMode|getLanguageMode)\(`
- **Replace with:** Remove the call; overlay behaviour comes from the site language configuration (fallback type). In v12 use `setLanguageAspect()`.
- **Automation:** manual
- **Changelog:** Deprecation-89938-DeprecatedLanguageModeInTypo3QuerySettings

## Extbase / dependency injection

### Extbase `ObjectManager`

- **Status:** deprecated v11.4, removed v12.0
- **Detect:** `ObjectManager(Interface)?::class|->objectManager->get\(|Extbase\\Object\\ObjectManager`
- **Replace with:** Constructor injection via `Configuration/Services.yaml` (`autowire: true`, `autoconfigure: true`, `public: false` defaults, resource `../Classes/*`). For prototypes with runtime arguments use `GeneralUtility::makeInstance(Foo::class, $arg)`. Classes fetched with `makeInstance()` that have constructor DI must be `public: true` (or be consumed by DI themselves).
- **Automation:** manual (Rector cannot infer your service graph)
- **Changelog:** Deprecation-94619-ExtbaseObjectManager

```yaml
services:
  _defaults:
    autowire: true
    autoconfigure: true
    public: false
  Vendor\MyExt\:
    resource: '../Classes/*'
    exclude: '../Classes/Domain/Model/*'
```

### `@Extbase\Inject` property injection

- **Status:** deprecated v11.0, removed v12.0; injection into non-public properties already removed in v11.0
- **Detect:** `@(TYPO3\\CMS\\Extbase\\Annotation\\Inject|Extbase\\Inject|inject)([[:space:]]|$)`
- **Replace with:** Constructor injection, or `injectFoo(Foo $foo): void` methods.
- **Automation:** Rector `\Ssch\TYPO3Rector\TYPO311\v0\ReplaceInjectAnnotationWithMethodRector`
- **Changelog:** Deprecation-92386-DeprecatedExtbasePropertyInjection

### `getInstance()` on singletons

- **Status:** `ResourceFactory::getInstance()` removed v11.0; other `::getInstance()` deprecated v11.5, removed v12.0
- **Detect:** `::getInstance\(\)`
- **Replace with:** Constructor injection or `GeneralUtility::makeInstance(ResourceFactory::class)` (same for `ExtractorRegistry`, `RendererRegistry`, `OnlineMediaHelperRegistry`, `MetaDataRepository`, `FileIndexRepository`, …).
- **Automation:** Rector `\Ssch\TYPO3Rector\TYPO310\v3\SubstituteResourceFactoryRector` for ResourceFactory; others manual
- **Changelog:** Deprecation-95326-VariousGetInstanceStaticMethodsOnSingletonInterfaces

### `LanguageService` from the container

- **Status:** deprecated v11.3
- **Detect:** `(makeInstance|get)\(LanguageService::class`
- **Replace with:** Inject `LanguageServiceFactory` and call `->createFromUserPreferences($GLOBALS['BE_USER'])` / `->createFromSiteLanguage($siteLanguage)` / `->create('de')`.
- **Automation:** manual
- **Changelog:** Deprecation-94414-DeprecateLanguageServiceContainerEntry

## Fluid

### Fluid widgets (`f:widget.paginate`, `f:widget.autocomplete`, custom widgets)

- **Status:** removed in v11.0
- **Detect:** `f:widget\.|AbstractWidgetController|AbstractWidgetViewHelper`
- **Replace with:** Pagination API in the controller (`QueryResultPaginator` / `ArrayPaginator` + `SimplePagination`, v12 adds `SlidingWindowPagination`) and your own pagination partial.
- **Automation:** manual
- **Changelog:** Breaking-92529-AllFluidWidgetFunctionalityRemoved

```php
$paginator = new QueryResultPaginator($items, $currentPage, 10);
$this->view->assignMultiple(['paginator' => $paginator, 'pagination' => new SimplePagination($paginator)]);
```

### `useCacheHash` / `noCacheHash` arguments

- **Status:** removed in v11.0 (deprecated v10.0)
- **Detect:** `useCacheHash|noCacheHash|setUseCacheHash`
- **Replace with:** Delete the argument/call; cHash is added automatically when needed.
- **Automation:** Fractor `a9f\Typo3Fractor\TYPO3v10\Fluid\RemoveNoCacheHashAndUseCacheHashAttributeFluidFractor`, `a9f\Typo3Fractor\TYPO3v10\TypoScript\RemoveUseCacheHashFromTypolinkTypoScriptFractor`; Rector (TYPO3_10 set) for `UriBuilder`

### `<f:be.container>` and module layout ViewHelpers

- **Status:** deprecated v11.3, removed v12.0
- **Detect:** `f:be\.container|f:be\.moduleLayout`
- **Replace with:** Render module output through `ModuleTemplate` (see backend cards) and use a Fluid layout; include assets with `<f:be.pageRenderer>`.
- **Automation:** manual
- **Changelog:** Deprecation-94225-FbecontainerViewHelper

## Utilities and database

- **Replace with:** `fetchAssociative()`, `fetchAllAssociative()`, `fetchOne()`, `fetchFirstColumn()`; `executeQuery()` / `executeStatement()` instead of `execute()` (verify availability on the TYPO3 `QueryBuilder` for your exact 11.5 patch level before relying on it).
